# Contributing

## Что относится к этому репозиторию (scope guard)

`ds` — слой ядра-хранилища (система записи). Прежде чем добавлять функциональность, свериться с
[`docs/explanation/scope-and-non-goals.md`](docs/explanation/scope-and-non-goals.md) и
[`docs/decisions/0007-scope-freeze-storage-core.md`](docs/decisions/0007-scope-freeze-storage-core.md).

**Входит:** приём данных, историзация, выдача состояния одного источника на момент времени
(Level 1), жизненный цикл (архив/удаление), управление сущностями схемы (merge/split/delete/
rename над `srcs`/`lbs`/`ids`/`vals`), миграции схемы, оптимизация.

**Не входит** (вышестоящий слой, отдельный проект): семантический маппинг, разрешение коллизий
между источниками по весам `p` (Level 2), управление приоритетами пользователем, любой UI,
доменная логика, BI. Доменная лексика в коде ядра — нежелательна.

## Ограничения

- Только стандартная библиотека Python (`>= 3.9`, целевая — `3.9.20`). `pytest` — только dev.
- SQLite, офлайн, одна нода, без сетевых портов. См.
  [`docs/decisions/0001-stdlib-only-sqlite-offline.md`](docs/decisions/0001-stdlib-only-sqlite-offline.md).
- Весь доступ к данным — через `StoragePort`; новые операции добавляются в порт и в **оба**
  адаптера (`SQLiteAdapter`, `InMemoryAdapter`), с тестами на паритет.

## Definition of Done

Изменение принято, когда:

1. Тесты зелёные: `./run_tests.sh` (Docker, Python 3.9.20).
2. Если поменялось наблюдаемое поведение (CLI, схема БД, форматы файлов, контракт порта) —
   обновлён соответствующий файл в [`docs/reference/`](docs/reference/).
3. Если добавлен/изменён пользовательский сценарий — обновлены или добавлены
   [`examples/`](examples/) (и `expected/` перегенерирован: `UPDATE_EXAMPLES=1 pytest tests/examples/`).
4. Архитектурное решение — оформлено как ADR в [`docs/decisions/`](docs/decisions/) (не
   правкой старого ADR, а новым, если меняется ранее принятое).
5. Изменение схемы БД — отражено пунктом в `releases/README.md` (отдельной версии схемы нет,
   см. [`docs/decisions/0008-no-separate-schema-versioning.md`](docs/decisions/0008-no-separate-schema-versioning.md)).

Документация — часть изменения, а не отдельная задача «потом».

## Ветки и релизы

- `main` — только стабильный релизный код без тестов.
- Тесты и dev-инструменты — в ветке разработки.
- Релиз — архив `releases/ds-<version>.tar.gz` (рабочий код без тестов) + пункт в
  `releases/README.md`.

## Документация: стиль

- Один аспект на файл, ~1 экран.
- Реализованное — в `reference/`/`explanation/`; запланированное — в `roadmap/`. Не в одном
  файле.
- В `reference/` примеры команд и вывод — из реального прогона, не по памяти. DDL —
  копия из кода. Проверяется примерами.
- Язык — русский; идентификаторы и имена полей — как в коде.
