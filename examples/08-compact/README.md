# 08 — `ds compact`: убрать записи, не менявшие значение

Классический кейс из обсуждения: показатель принял значение X (момент 1), затем снова X
(момент 2 — избыточно, ничего не изменилось), затем Z (момент 3 — настоящее изменение).
Вторая запись со значением X не несёт информации: срез на любой момент времени между 1 и 3
будет показывать X независимо от того, существует она или нет — значит её можно безопасно
убрать. `ds compact` находит такие записи для каждой пары (показатель, ключ) и переносит их
в архив (по умолчанию) либо удаляет физически (`--hard`) — теми же примитивами, что уже
умеют `ds archive`/`ds delete` (`txn_archive(cnts=...)`/`txn_delete(cnts=...)`).

## Запуск

```bash
bash run.sh /tmp/ex08
```

```
--- ds compact --src CRM --yes ---
archived 1 duplicate transaction(s)

--- ds get --archive: 3 транзакции на месте, просто одна теперь в архиве ---
{ ..., "data": [{"customer_id": "1", "status": "inactive"}] }
```

Без `--yes` команда сперва покажет число найденных дублей и несколько примеров
(`источник.показатель.ключ @ dt = значение`), и только потом спросит подтверждение.

## `--dt-from`/`--dt-until`: диапазон без необходимости смотреть за его границы

Если задать `--dt-from`, самая первая запись **в этом диапазоне** по каждому ключу считается
опорной и никогда не помечается дублем — даже если бы оказалась дублем более ранней записи,
не попавшей в диапазон. Так дедупликацию можно ограничить последним периодом, не боясь
случайно «потерять контекст» из-за отрезанной истории:

```bash
ds --db data.db compact --src CRM --dt-from 1704153600 --yes
# batch2 (dt=1704153600) становится опорной точкой окна и не помечается дублем,
# даже притом что batch1 (вне окна) имел то же значение
```
