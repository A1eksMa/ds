# 12 — `mv` переименование показателя с переходным периодом

Источник переименовал показатель «Изготовитель» → «Производитель». Новые данные уже
начали приходить под новым именем для части ключей, пока остальные ещё числятся под
старым — ровно ситуация, ради которой написан `ds mv`.

```bash
ds --db data.db mv --src SRC --lb OLD_LB --to-lb NEW_LB [--yes]
```

- `--to-src` не задан → по умолчанию тот же источник, что `--src` (переименование на
  месте, а не перенос между источниками — см. [`13-mv-cross-source`](../13-mv-cross-source/)
  для второго случая);
- если `--to-lb` **ещё не существует** в источнике — создаётся, старая метка просто
  переименовывается (в терминах реализации — все её транзакции переезжают на новый
  `lb_id`, старый удаляется из пула);
- если `--to-lb` **уже существует** (как здесь — клиент 102 уже получил пару
  транзакций под новым именем) — история обеих меток сливается в одну: более новая
  транзакция побеждает при свёртке `ds get`, как и для любой другой пары дублирующих
  записей одного показателя;
- `--yes` — не спрашивать подтверждение (без него — точный счётчик затронутых
  транзакций и вопрос `[y/N]`, как у `archive`/`delete`/`unarchive`).

Старая метка («Изготовитель») после `mv` полностью исчезает из `lbs` — не остаётся
сиротой без единой ссылающейся транзакции.

## Запуск

```bash
bash run.sh /tmp/ex12
```

```
--- ds get: обе метки существуют параллельно (переходный период) ---
{ ..., "labels": ["Изготовитель", "Производитель"], "data": [

  {"customer_id": "102", "Изготовитель": "ООО Лютик", "Производитель": "ООО Лютик-Нью"}

```
