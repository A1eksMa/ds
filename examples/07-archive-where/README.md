# 07 — `archive`/`delete` по условию на значение показателя (`--where`)

`ds archive`/`ds delete` понимают общий набор селекторов «что затронуть» (единственная
разница между ними — конечное действие: переместить в архив или стереть безвозвратно):

- `--src NAME` (обязателен всегда);
- `--lb NAME` (повторяемый) — какие показатели, по умолчанию все;
- `--id VALUE` (повторяемый) — какие ключи, по умолчанию все;
- `--where LB=VALUE` — альтернатива `--id`: ключи вычисляются сверткой (Level 1, активные +
  архивные транзакции, «на сейчас») показателя `LB` — берутся те, где текущее значение равно
  `VALUE`. Затрагивает **все** показатели найденных ключей, если `--lb` не сужен отдельно;
- `--cnt N` (повторяемый) — конкретные записи по номеру счётчика; самостоятельный режим, не
  сочетается с перечисленным выше;
- `--dt-from`/`--dt-until` — диапазон бизнес-времени записи (`dt`);
- `--created-from`/`--created-until` — диапазон времени физической загрузки в БД (`created_at`);
- `--yes` — не спрашивать подтверждение.

Этот пример — самый показательный кейс `--where`: признак `is_test_account` истинен для
клиента 102 — архивируем его целиком (все показатели), не трогая двух остальных.

## Запуск

```bash
bash run.sh /tmp/ex07
```

```
--- ds get: все три клиента активны в основной таблице ---
{ ..., "rows": 3, ... }

--- ds archive --where is_test_account=true --yes ---
archived 2 transaction(s)

--- ds get: клиент 102 (test-аккаунт) пропал из основной таблицы целиком ---
{ ..., "rows": 2, "data": [{"customer_id": "101", ...}, {"customer_id": "103", ...}] }

--- ds get --archive: 102 виден при явном запросе архива, вместе с email ---
{ ..., "rows": 3, "data": [..., {"customer_id": "102", "email": "bob@e.com", "is_test_account": "true"}] }
```
