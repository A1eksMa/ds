# 10 — `ds upload`: строгая загрузка для файла, в происхождении которого нет уверенности

`ds upload` делает то же, что `ds load`, но сначала проверяет, что файл **целиком** укладывается
в уже известную схему источника — и если нет, не грузит вообще ничего (ни одной строки, даже из
столбцов, которые были бы в порядке). Два условия:

1. **Каждый столбец (кроме `key_label`) уже известен** — либо когда-то раньше загружался для
   этого источника, либо заранее объявлен в `labels[]` `source.json` (как здесь — `email` и
   `revenue` объявлены оба, поэтому `ds upload` работает даже без единой предыдущей загрузки).
2. **Каждое значение парсится под объявленный тип** (`labels[].type`) — показатель без
   объявленного типа трактуется как `text` (без ограничений).

## Запуск

```bash
bash run.sh /tmp/ex10
```

```
--- ds upload: email/revenue объявлены заранее, типы совпадают -> проходит ---
uploaded 2 transaction(s)

--- ds upload: utm_source не объявлен и раньше не грузился -> отказ целиком ---
error: unknown label 'utm_source' -- not previously loaded for 'CRM' and not declared in its source.json

--- ds upload: revenue = 'fifty dollars' не парсится как number -> отказ целиком ---
error: value 'fifty dollars' at row 0 does not parse as declared type 'number'

--- ds get: только первая (успешная) загрузка реально попала в БД ---
{ ..., "rows": 1, "data": [{"customer_id": "1", "email": "a@x.com", "revenue": "100"}] }
```

Оба отклонённых батча (`unknown_label.json`, `bad_type.json`) не оставили в БД ни следа —
`ds get` после них видит только клиента `1` из первой, успешной загрузки.
