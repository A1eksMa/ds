## Направления

### Индексы под конкретные запросы

Текущие индексы покрывают фильтр по времени и группировку по `(src, lb, id)`. С появлением
`ds get` / свёртки могут понадобиться:
- частичный/покрывающий индекс под «последняя транзакция на `(src, lb, id)`»;
- ~~индекс по `cnt` для инкрементального чтения (`from_cnt`)~~ — **сделано** (`ds get
  --cache`, [ADR-0010](../decisions/0010-incremental-fold-cache.md)), без отдельного
  нового индекса: `cnt` уже `PRIMARY KEY` в обеих таблицах транзакций.
Добавлять по факту медленных запросов, не заранее.

### Дедупликация

- **Транзакций — сделано.** `ds compact` (см.
  [`lifecycle-cli.md`](lifecycle-cli.md), [`../reference/cli.md#ds-compact`](../reference/cli.md#ds-compact))
  находит и архивирует/удаляет транзакции, повторяющие значение, уже действовавшее для той же
  пары (показатель, ключ) — покрывает и «легитимное повторное значение с бизнес-точки зрения не
  несёт информации» (общий случай), и его частный случай «повторная загрузка того же файла»
  (при том же `dt` вставленная копия окажется соседней по `(dt, cnt)` с тем же значением — тоже
  дубль). Ключевое отличие от `optimization`-задач ниже: это не про побайтово идентичные строки
  журнала, а про то, меняет ли строка фактический срез `ds get` — поэтому и живёт в
  `lifecycle-cli`, а не здесь.
- **Значений в `vals`/`ids`.** `UNIQUE` уже не даёт дублей на вставке; чистить нужно
  осиротевшие (после архива/удаления/merge) записи, на которые больше нет ссылок — см. «Чистка
  осиротевших записей пулов» ниже.

### Чистка осиротевших записей пулов

После `txn_delete` и будущего merge ([`entity-curation.md`](entity-curation.md)) в `vals` /
`ids` / `lbs` остаются записи без ссылок из журнала. Нужна операция `purge` (`DELETE ... WHERE
NOT EXISTS (SELECT 1 FROM transactions_full ...)`), затем `VACUUM`.

### `VACUUM` / компактизация

После крупных удалений/архивирования файл БД не уменьшается сам. `ds vacuum` или флаг у
операций жизненного цикла.

### Профилирование

Набор реалистичных по объёму тестовых БД (в [`../../examples/`](../../examples/) или
отдельно) + замеры времени ключевых операций, чтобы регрессии производительности были видны.
Готовит почву для переписывания горячих путей на C/CPython-расширения
([`../explanation/constraints.md`](../explanation/constraints.md)).
