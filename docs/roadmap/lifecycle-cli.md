# [roadmap] Жизненный цикл данных в CLI

> **Статус: частично.** Операции есть в `StoragePort` (`txn_archive`, `txn_delete`),
> но в `ds` не выведены. Пока — только из Python, см.
> [`../guides/archiving-via-python.md`](../guides/archiving-via-python.md).

## Что нужно

Подкоманды `ds` поверх существующих методов порта:

| Команда (черновой вид) | Метод порта | Смысл |
|---|---|---|
| `ds archive --until-dt TS` | `txn_archive(until_dt)` | перенести транзакции с `dt <= TS` в `transactions_archive` |
| `ds delete --src NAME [--lb NAME]` | `txn_delete(src_id, lb_id=None)` | физически удалить транзакции источника (опц. одной метки) |
| `ds restore --until-dt TS` (?) | — | обратный перенос из архива — метода пока нет |

## Вопросы к проработке

- Резолв `--src` / `--lb` по имени без побочных эффектов (как в снятом `ds get`): неизвестное
  имя → `NotFound`, не создавать запись.
- Подтверждение для необратимого `delete` (флаг `--yes` / интерактивный вопрос).
- Вывод: сколько записей перемещено/удалено, код возврата.
- Транзакционность: обе операции — под `begin()/commit()`.
- Нужна ли операция `restore` (обратный перенос из архива) и `purge` осиротевших записей
  пулов — пересекается с [`optimization.md`](optimization.md).
- Взаимодействие с курацией сущностей: удалять источник целиком → сначала его транзакции,
  потом метки (FK `RESTRICT`).
