# Веса доверия `p`

## Что это

`p` — число `[0.0 .. 1.0]`, характеризующее достоверность данных: `1.0` — максимальное
доверие, `0.0` — минимальное. Веса есть на трёх уровнях:

| Уровень | Поле | По умолчанию |
|---|---|---|
| источник | `srcs.p` | `0.5` |
| показатель | `lbs.p` | `0.5` (не наследуется от источника) |
| отдельная запись | `transactions.p` | `1.0` (при загрузке всегда пишется `1.0`) |

Итоговый вес записи задуман как произведение:

```
p_total = p_source × p_label × p_record
```

## Где `p` применяется — и где нет

- **Хранится** в ядре: поля в схеме есть, читаются и пишутся.
- **Применяется** (сравнение `p_total` для выбора значения между источниками — Level 2)
  **вне ядра**, в слое обработки. См. [`scope-and-non-goals.md`](scope-and-non-goals.md),
  [`single-source-fold.md`](single-source-fold.md).

Ядро — система записи: оно фиксирует, какой вес назначен, но не решает на его основе, «чьё
значение победит».

## Текущие ограничения реализации (0.5.0a1)

- **`p` из `source.json` не доходит до БД.** Загрузчик его парсит и валидирует диапазон, но
  при `src_get_or_create` не передаёт — у источника всегда останется `0.5`. Чтобы задать вес,
  сейчас нужен прямой `UPDATE srcs SET p = ...` (в порту это `src_update`, в CLI не выведено).
  То же для `lbs.p`.
- Конфиги показателей (`labels/<name>/config.json`) загрузчик не читает вовсе.

Это известные разрывы, не проектное решение — см.
[`../reference/config-format.md`](../reference/config-format.md).

## Свойства модели (как задумано)

- Веса в БД можно менять в любой момент; они **не версионируются** (не привязаны ко времени).
  При изменении веса **все** исторические запросы пересчитаются с новым значением.
- Вес показателя приоритетнее общего веса источника (для того `lbs.p` и отделён от `srcs.p`).
- Доверие — **составное** (`dt × p`), а не бинарная проверка правдоподобия. Задача «можно ли
  доверять этим данным» решается весом, а не подменой бизнес-времени `dt` на системный `cnt`
  — это обсуждалось при выработке правила свёртки, см.
  [`../decisions/0006-fold-order-dt-cnt.md`](../decisions/0006-fold-order-dt-cnt.md).
