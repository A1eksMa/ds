# Журнал транзакций вместо обновления «на месте»

## Решение

`ds` не хранит «текущее значение» показателя и не перезаписывает его. Каждое изменение
дописывается в журнал `transactions` отдельной строкой. Актуальное состояние получается
**проигрыванием** журнала до нужного момента (см. [`single-source-fold.md`](single-source-fold.md)).

Журнал — **append-only**: строки не меняются и не удаляются в ходе обычной работы. Изменение
значения — это новая транзакция, а не `UPDATE`.

## Зачем

| Свойство | Что даёт |
|---|---|
| Полная история (audit trail) | Видно каждое значение показателя за всё время и кто/когда его сообщил. |
| «Машина времени» | Состояние восстанавливается на **любой** прошлый момент, а не только на «сейчас». См. [`time-model.md`](time-model.md). |
| Нет потери данных при обновлении | Старое значение не затирается, оно остаётся в журнале. |
| Обработка задержанных и несинхронных источников | Данные «за вторник», пришедшие в пятницу, просто дописываются с нужным `dt` — пересборка любого среза учтёт их. |
| Прозрачное происхождение данных (data lineage) | Каждая четвёрка привязана к источнику и двум отметкам времени. |

## Цена решения

- **Чтение — это вычисление.** «Текущее значение» не лежит готовым, его каждый раз
  сворачивают из журнала. Отсюда в первоначальном замысле были снэпшоты/чекпоинты (таблица
  `state`) — в ядре их пока нет, см. [`../reference/get-output-format.md`](../reference/get-output-format.md).
- **Журнал только растёт.** Управление объёмом — через архивирование и физическое удаление
  (жизненный цикл данных), см. [`../roadmap/lifecycle-cli.md`](../roadmap/lifecycle-cli.md).
- **Повторная загрузка того же файла — это новые транзакции, а не идемпотентная операция.**
  Загрузил один батч дважды — в журнале два комплекта строк.

## Напряжение с управлением сущностями

`merge`/`split`/`delete` над метками и источниками (см.
[`entity-curation.md`](entity-curation.md)) по своей природе конфликтуют с «журнал
неизменяем»: свести две метки в одну — значит либо переписать историю, либо завести слой
алиасов. Это открытый вопрос — [`../decisions/0009-entity-curation-rewrite-vs-events.md`](../decisions/0009-entity-curation-rewrite-vs-events.md).

## Родственные понятия

Тот же подход в других областях называют **Slowly Changing Dimensions (SCD2/SCD4)** (хранилища
данных), **temporal tables** (SQL:2011), **snapshot-based CDC** (для детекта изменений при
загрузке — см. [`act-semantics.md`](act-semantics.md)).
