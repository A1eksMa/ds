# Семантика удаления: `val = NULL`

## Что означает `DELETE`

Когда во входных данных на месте значения стоит `null`, `ds` пишет транзакцию с `act = DELETE`
и `val = 0` (в домене — `ValId(0)`; в БД — `transactions.val IS NULL`). `val_id`
нумеруется с 1, поэтому `0` — это не ссылка на пул, а маркер «значения нет».

Это **логическое удаление**: не «забыть, что показатель был», а зафиксировать факт
«на момент `dt` источник сообщил, что значения больше нет».

## Как это ведёт себя при свёртке

- `DELETE` — обычная транзакция в журнале, она участвует в определении «последней» наравне с
  `POST`/`PATCH`.
- Если последней по порядку оказалась `DELETE`, в состоянии для ключа `(src, lb, id)` остаётся
  **явная запись** со значением `null`, а не отсутствие ключа.
- Последующая непустая загрузка того же показателя → `PATCH` (повторное появление после
  удаления), см. [`act-semantics.md`](act-semantics.md).

## «Удалено» ≠ «никогда не было»

Это разные ситуации, и они по-разному выглядят в выгрузке состояния:

| Ситуация | В состоянии |
|---|---|
| Показатель был, потом пришёл `null` | ключ `(src, lb, id)` присутствует, `val = null` |
| Показателя для объекта не было ни в одной транзакции | ключа `(src, lb, id)` в состоянии просто нет |

## Область действия

`DELETE` действует **в пределах одного источника** — исключает значение из расчётов этого
источника до следующего `POST`/`PATCH`. Как несколько источников с разными значениями (в т.ч.
с удалением у одного из них) сводятся вместе — вопрос Level 2, который в ядре не решается
(см. [`scope-and-non-goals.md`](scope-and-non-goals.md)).

## Физическое удаление — это другое

`DELETE`-транзакция ничего не стирает из БД. Безвозвратное удаление строк журнала по критерию
— отдельная операция жизненного цикла (`txn_delete`), не выведённая в CLI, см.
[`../roadmap/lifecycle-cli.md`](../roadmap/lifecycle-cli.md).
