# Метки специфичны для источника

## Решение

`lbs` уникальна по паре **`(src_id, name)`**, а не по `name`. Одноимённый показатель в двух
источниках — это **две разные записи** с разными `lb_id`.

```sql
CREATE TABLE lbs (
    lb_id  INTEGER PRIMARY KEY AUTOINCREMENT,
    name   TEXT    NOT NULL,
    p      REAL    NOT NULL DEFAULT 0.5,
    src_id INTEGER NOT NULL,
    UNIQUE (src_id, name),
    FOREIGN KEY (src_id) REFERENCES srcs(src_id) ON DELETE RESTRICT
);
```

Реализовано в 0.5.0a1 (было решением #4 в старом `TODO.md`), ADR —
[`../decisions/0005-source-specific-labels.md`](../decisions/0005-source-specific-labels.md).

## Почему

**Метка существует только в контексте источника, а не сама по себе.**

- Одинаковое имя в разных источниках может означать **разные** сущности: `status` в CRM и
  `status` в биллинге — про разное.
- Разные имена в разных источниках могут означать **одну** сущность: `Производитель` в одном,
  `Manufacturer` в другом.
- Совпадение имени — не гарантия совпадения смысла, и наоборот.

Глобальный пул меток по имени в этой модели **некорректен по определению**, а не просто
неудобен: он молча склеил бы разные показатели в один `lb_id`.

## Что это ломает и как это обходится

**Циклическая зависимость `Src` ↔ `Lb`.** `srcs.key_label` — FK на `lbs`, а `lbs.src_id` —
FK на `srcs`. Обе записи одним шагом не создать. Порядок бутстрапа:

1. Создать `Src` с `key_label = NULL`.
2. Интернировать ключевую метку — уже с `src_id` из шага 1.
3. `src_set_key_label(src_id, lb_id)` — дозаписать `srcs.key_label`.

Поэтому `srcs.key_label` — **nullable**, а `Src.key_label` в домене — `Optional[LbId]`.

## Следствие для будущего Level 2

Раз имя метки больше не свидетельствует о тождестве показателей между источниками, будущий
слой обработки **не может** сопоставлять их по `lb_id` или по имени — ему нужен отдельный
явный слой соответствия («канонический показатель ↔ `(src, lb)`»). В ядре его нет и не будет
(см. [`scope-and-non-goals.md`](scope-and-non-goals.md)). Механическую часть — свести два
`lb_id` в один, когда решение о тождестве уже принято — закрывает
[`../roadmap/entity-curation.md`](../roadmap/entity-curation.md).
