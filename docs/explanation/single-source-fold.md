# Свёртка состояния одного источника (Level 1)

> **Статус в коде:** функций `fold_state` / `build_state` и команды `ds get` сейчас нет —
> сняты в 0.5.0a1 вместе с остальным Processing Engine ради минимума кода. Здесь описана
> **целевая** модель. Реализация — [`../roadmap/state-retrieval.md`](../roadmap/state-retrieval.md).

## Что такое свёртка

Журнал хранит все изменения (см. [`event-sourcing.md`](event-sourcing.md)). «Состояние» —
это по одному актуальному значению на ключ `(src, lb, id)` на заданный момент времени.
Свёртка (fold) берёт список транзакций и оставляет для каждого ключа «победителя».

## Два уровня коллизий

| Уровень | Коллизия | Правило | Где |
|---|---|---|---|
| **Level 1** | несколько значений одного показателя **внутри одного источника** | приоритет по бизнес-времени `dt`; при равенстве — по `cnt` | **ядро** (этот документ) |
| **Level 2** | значения одного показателя **из разных источников** | приоритет по весам доверия `p_source × p_label × p_record` | **вне ядра** — [`trust-weights.md`](trust-weights.md), [`scope-and-non-goals.md`](scope-and-non-goals.md) |

`ds get` отдаёт результат **Level 1**: по записи на каждый `(src, lb, id)`. Если один и тот
же `(lb, id)` есть в нескольких источниках, в выгрузке будет **несколько строк** — по одной
на источник. Выбор «чьё значение главнее» ядро не делает.

## Порядок разрешения внутри источника (целевое правило)

Ключ сортировки — `(dt, cnt)`, побеждает последний:

1. **Больший `dt`** (бизнес-время) — более поздние данные приоритетнее.
2. **При равном `dt` — больший `cnt`** — тот, кто физически вставлен позже. `cnt` —
   единственное гарантированно неповторяющееся поле (см. [`time-model.md`](time-model.md)).

Сортировка **не** по `cnt` в одиночку: более ранняя по бизнес-времени запись может попасть в
БД позже (задержка источника) и не должна затирать более новую. Это уточнённое решение
относительно того, что было в 0.3.0a1 (там победитель определялся по `cnt`) — история
вопроса в [`../decisions/0006-fold-order-dt-cnt.md`](../decisions/0006-fold-order-dt-cnt.md).

## `DELETE` при свёртке

`val = 0` (`DELETE`) остаётся в состоянии как явная запись со значением `null`, а не
выкидывается из результата. См. [`delete-semantics.md`](delete-semantics.md).

## «Машина времени»

Свёртке предшествует фильтр `dt <= T` (и опционально включение архива). Меняя `T`, получаем
состояние на любой прошлый момент.
