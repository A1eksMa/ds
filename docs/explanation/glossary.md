# Глоссарий

Термины и сокращения, на которые ссылается остальная документация. Имена совпадают с полями
в коде и в схеме БД.

| Термин | Расшифровка | Пояснение |
|---|---|---|
| **source**, `src` | источник информации | Отдельная система, из которой приходят выгрузки: «CRM», «ERP», «Website». Таблица `srcs`, ссылка `transactions.src`. |
| **label**, `lb` | показатель / индикатор / заголовок столбца | «Email», «Phone», «Price». Специфичен для источника (см. [`source-specific-labels.md`](source-specific-labels.md)). Таблица `lbs`. |
| **id** | идентификатор объекта | Значение ключевого показателя источника для конкретной строки: `customer_id = "101"`. Пул `ids`, ссылка `transactions.id`. |
| **value**, `val` | значение показателя | «alice@example.com», «+7-900-000-0001». Пул `vals`. `val = 0` (не ссылка) означает `DELETE` — см. [`delete-semantics.md`](delete-semantics.md). |
| **key_label** | ключевой показатель источника | Столбец во входных данных, содержащий уникальные `id` объектов: `customer_id`, `product_id`. Задаётся в `source.json`. Хранится как `srcs.key_label` (FK на `lbs`). |
| **transaction** | одна запись в журнале | Факт «показатель `lb` объекта `id` из источника `src` в бизнес-момент `dt` получил значение `val` операцией `act`». Неизменяема. Таблица `transactions`. |
| **act** | тип операции над значением | `POST` (перезапись существующего), `PATCH` (первое появление или после удаления), `DELETE` (`val = NULL`), `GET` (зарезервирован, не пишется). Определяется автоматически при загрузке — [`act-semantics.md`](act-semantics.md). Пул `acts`. |
| **dt** | бизнес-время | Unix-timestamp «с какого момента данные считаются актуальными». Задаётся извне (`--dt`), может быть любым, в т.ч. в прошлом. |
| **created_at** | физическое время вставки | Unix-timestamp «когда запись реально попала в БД». Генерируется хранилищем один раз. Отдельно от `dt`. Нужен, чтобы объяснять расхождения отчётов при задержанной доставке. |
| **cnt** | порядковый номер транзакции | `INTEGER PRIMARY KEY`, монотонно растёт, глобально уникален (в т.ч. между основной и архивной таблицами). Порядок вставки в хранилище. Ссылка на `cnts.cnt_id`. |
| **p** | вес доверия | Число `[0.0 .. 1.0]`. Есть у источника (`srcs.p`), показателя (`lbs.p`) и записи (`transactions.p`). По умолчанию `0.5` для метаданных, `1.0` для записи. Как применяется — [`trust-weights.md`](trust-weights.md). |
| **state** | свёрнутое состояние | Результат «проигрывания» журнала: по одному актуальному `val` на ключ `(src, lb, id)` на заданный момент. Считается на лету при `ds get` (`src/service/get.py`), нигде не персистится — [`single-source-fold.md`](single-source-fold.md), [`../reference/get-output-format.md`](../reference/get-output-format.md). **Таблицы `state` в схеме нет.** |
| **string pool** | справочная таблица строк | `srcs`, `lbs`, `ids`, `vals`, `acts` — хранят уникальные строки; в журнале только целочисленные ссылки. [`dictionary-encoding.md`](dictionary-encoding.md). |
| **Level 1 / Level 2** | уровни свёртки | Level 1 — коллизии внутри одного источника (по времени), **в ядре**. Level 2 — коллизии между источниками (по весам `p`), **вне ядра**. |
| **event sourcing** | подход к хранению | Изменения не перезаписывают данные, а дописываются в журнал; состояние восстанавливается проигрыванием. [`event-sourcing.md`](event-sourcing.md). |
| **битемпоральность** | две (три) оси времени | `dt` — время предметной области, `created_at` — время системы. [`time-model.md`](time-model.md). |
| **golden record** | «золотая запись» | Одно согласованное значение показателя после разрешения противоречий между источниками. Считается **вне ядра**. |
