# Справочники строк (string pools)

## Решение

Все текстовые данные — имена источников, названия показателей, значения `id`, значения
показателей — хранятся в отдельных справочных таблицах:

| Пул | Что хранит |
|---|---|
| `srcs` | имена источников (+ метаданные) |
| `lbs` | названия показателей (+ метаданные) |
| `ids` | значения идентификаторов объектов |
| `vals` | значения показателей |
| `acts` | названия операций (`POST`/`PATCH`/`DELETE`/`GET`) |

В журнале `transactions` вместо строк — **целочисленные ссылки** на эти пулы.
Операция «строка → её целочисленный id, создать если нет» называется **интернированием**
(`*_intern` в [`../reference/storage-port.md`](../reference/storage-port.md)).

## Зачем (dictionary encoding)

- **Экономия места.** Значение `"alice@example.com"`, встречающееся в 10000 транзакций,
  хранится один раз; в журнале — 10000 раз по 8 байт вместо 10000 строк.
- **Быстрее сравнения и группировки.** `INTEGER` вместо `TEXT` в `WHERE`, `JOIN`, `GROUP BY`.
- **Компактные индексы** по `(src, lb, id)`.
- **Меньше RAM** при обработке журнала.

## Гибридная стратегия кеширования

Пулы неравноценны по размеру:

- **Маленькие, часто используемые** (`srcs`, `lbs`, `acts`, отчасти `ids`) — кешируются в
  памяти адаптера целиком при старте (`SQLiteAdapter._load_small_pools`). Интернирование
  такого значения не ходит в БД, если оно уже в кеше.
- **Большой** (`vals`) — растёт линейно с объёмом данных, целиком в память не помещается;
  работает обычными запросами с `UNIQUE`-индексом, без предзагрузки.

Это компромисс «простота ↔ производительность при ограничении по RAM» — см.
[`../decisions/0003-string-pools-hybrid.md`](../decisions/0003-string-pools-hybrid.md).

## Следствия

- `id` уникален в пуле `ids` **глобально**, не в рамках источника (см.
  [`data-model.md`](data-model.md)).
- `lbs` уникальна по паре `(src_id, name)`, а не по `name` — см.
  [`source-specific-labels.md`](source-specific-labels.md).
- В пуле со временем копятся значения, на которые уже никто не ссылается (после архивирования
  и удаления). Их вычистка — задача жизненного цикла, см.
  [`../roadmap/optimization.md`](../roadmap/optimization.md).
