# Автоопределение типа операции при загрузке

## Что это

У каждой транзакции есть `act` — тип операции над значением, в стиле REST:

| `act` | Когда |
|---|---|
| `PATCH` | для пары `(lb, id)` под этим источником раньше не было значения, **либо** последняя запись была удалением (первое появление / повторное появление) |
| `POST` | для пары `(lb, id)` уже есть значение — оно перезаписывается |
| `DELETE` | во входных данных `null` — значение логически удаляется (`val = 0`), см. [`delete-semantics.md`](delete-semantics.md) |
| `GET` | зарезервирован в перечислении `Act`, при загрузке не пишется |

## `act` не задаётся вручную

Раньше (до 0.2.0a1) тип операции указывался флагом `--act` на весь файл. Сейчас он
**определяется автоматически на каждую ячейку**: `ds` перед вставкой батча одним запросом
(`txn_last_values`) поднимает последнее известное значение по всем парам `(lb, id)` из файла
— с учётом архива — и для каждой ячейки решает `PATCH`/`POST`/`DELETE` сам.

Это по сути **snapshot-based CDC**: входной файл — это полный срез источника, а `ds`
вычисляет дельту относительно того, что уже в журнале.

## Почему это разумно

- Источник присылает **срез состояния**, а не список изменений. Он не знает и не обязан
  сообщать, что для него ново, а что — правка. Классификацию делает `ds`.
- Указывать `--act` на весь файл было неверно: в одной выгрузке обычно есть и новые объекты
  (`PATCH`), и изменившиеся (`POST`).

## Точность различия `PATCH` / `POST`

Различие смысловое, а не техническое: обе операции просто вставляют строку с новым `val`.
`PATCH` vs `POST` — это метка «появилось впервые» vs «изменилось», полезная при разборе
истории объекта. На свёртку состояния (кто победит) `act` не влияет — влияют `dt` и `cnt`
(см. [`single-source-fold.md`](single-source-fold.md)).

## Замечания

- Ключевой показатель (`key_label`) сам по себе транзакций не порождает — он только даёт `id`
  для остальных ячеек строки.
- Повторная загрузка того же файла даст `POST` там, где в первый раз был `PATCH` — потому что
  история уже есть.
