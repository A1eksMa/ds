# Обзор: что такое `ds` и зачем он

## Одной фразой

**`ds`** — встраиваемый движок хранения данных с фиксированной схемой и набор инструментов
инженера данных для работы с ним. Он принимает периодические плоские выгрузки из разнородных
систем-источников, хранит все изменения как неизменяемый журнал и позволяет восстановить
состояние данных на любой момент времени.

## Какую проблему решает

Данные об одних и тех же объектах (клиентах, товарах, договорах) приходят из разных систем —
CRM, ERP, выгрузки с сайта, отчёты. Каждая система присылает **плоскую таблицу** — срез своего
состояния на какой-то момент. Эти срезы:

- приходят с разной периодичностью и с задержками (данные за вторник могут долететь в пятницу);
- частично противоречат друг другу;
- меняются во времени (значение показателя вчера и сегодня — разное);
- иногда меняют структуру (показатель переименовали, источник разделили).

Ручная сверка такого не масштабируется. `ds` даёт для этого **фундамент**: место, где всё
исходное складывается без потерь, с полной историей и атрибуцией «кто, что, когда сообщил»,
и откуда это можно поднять на любой прошлый момент времени.

## Роль в общей архитектуре: система записи

`ds` — это **нижний слой** многослойной системы, **система записи** (system of record):
авторитетное, неизменяемое, историзированное хранилище. Он отвечает на вопрос
*«что было заявлено источниками и когда»*, но **не** на вопрос *«чему из этого верить»* —
последнее считает вышестоящий слой.

```
┌─────────────────────────────────────────────────────────────┐
│  Обвес (свой у каждой предметной области)                    │
│  скрипты подготовки данных · SQL-отчёты · BI · будущий UI    │
└───────────────┬─────────────────────────────────────────────┘
                │
┌───────────────┴─────────────────────────────────────────────┐
│  Слой обработки (отдельный проект, ещё не начат)             │
│  семантический маппинг · разрешение коллизий между           │
│  источниками по весам доверия (Level 2) · управление         │
│  приоритетами и состояниями пользователем                    │
└───────────────┬─────────────────────────────────────────────┘
                │  контракт = формат хранения + тег версии ds
┌───────────────┴─────────────────────────────────────────────┐
│  ЯДРО — этот репозиторий (system of record)                  │
│  приём · историзация · выдача состояния источника на момент  │
│  времени · жизненный цикл (архив/удаление) · управление      │
│  сущностями схемы (merge/split) · миграции · оптимизация     │
└─────────────────────────────────────────────────────────────┘
```

Границы ядра подробно — в [`scope-and-non-goals.md`](scope-and-non-goals.md).
