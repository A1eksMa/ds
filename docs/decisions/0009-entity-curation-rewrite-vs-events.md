# 0009. merge/split сущностей: переписывать журнал или моделировать событиями?

- **Статус:** Открыто (решение не принято)
- **Дата:** 2026-08-29

## Контекст

Ядру нужен инструментарий управления сущностями схемы: свести две метки в одну (переименование
показателя во времени: «Производитель» → «Изготовитель»), разделить конфлатившую метку, слить
источники, почистить дубли в `ids` (см. [`../explanation/entity-curation.md`](../explanation/entity-curation.md),
[`../roadmap/entity-curation.md`](../roadmap/entity-curation.md)).

Эти операции конфликтуют с инвариантом «журнал неизменяем» ([ADR-0002](0002-event-sourcing-journal.md)).

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Переписать журнал** — `UPDATE transactions SET lb = :keep WHERE lb = :drop`, затем удалить строку пула. Трактуется как админ-миграция вне event-модели. | Чистый журнал; один `lb_id` на понятие; читателям (в т.ч. верхнему слою) ничего знать не нужно. | Нарушает append-only; нужна аккуратность с `transactions_archive` и FK `RESTRICT`; необратимо без бэкапа. |
| **B. Слой алиасов** — `lbs.merged_into` (или таблица соответствий), резолв на чтении. | Неизменяемость сохранена; обратимо. | Сложность у каждого читателя; «две метки» физически остаются; усложняет все выборки и будущий `ds get`. |
| **C. Отдельные события слияния** в самом журнале (спец. `act`). | В духе event sourcing. | Свёртка усложняется; неясно, как это выглядит для внешнего потребителя состояния. |

## Открытые подвопросы

- Ищет ли ядро **кандидатов** на merge механически (одноимённые метки в непересекающихся
  диапазонах `dt`; источники с похожими именами), или принимает только явную инструкцию
  «слей X и Y».
- Как split задаёт предикат разбиения транзакций.
- Нужна ли операция логироваться (кто/когда слил) отдельно от журнала данных.

## Следующий шаг

Принять решение до начала реализации `../roadmap/entity-curation.md`. Вероятный дефолт — **A**
(переписывание как явная админ-операция), поскольку верхний слой не должен знать про алиасы, а
контракт состояния должен оставаться простым.
