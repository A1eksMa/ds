# 0003. Справочники строк + гибридное кеширование

- **Статус:** Принято
- **Дата:** 2025-11-01

## Контекст

В журнале много повторяющихся строк: имена источников/показателей, значения id и значений
показателей. Хранить их построчно — дорого по месту и медленно по сравнению. При этом
ограничение по RAM (см. [ADR-0001](0001-stdlib-only-sqlite-offline.md)) не позволяет держать
всё в памяти.

## Решение

**Dictionary encoding:** все строки — в справочных таблицах (`srcs`, `lbs`, `ids`, `vals`,
`acts`); в `transactions` — только целочисленные ссылки. Операция «строка → id, создать если
нет» — интернирование.

**Гибридная стратегия кеша:**
- маленькие часто используемые пулы (`srcs`, `lbs`, `acts`, отчасти `ids`) — кешируются в
  памяти адаптера целиком при старте;
- большой пул `vals` — обычные запросы с `UNIQUE`-индексом, без предзагрузки.

## Альтернативы

- Отдельный компонент «String Pool Manager» с классами `small_pool`/`large_pool` (первоначальный
  `COMPONENTS_ARCHITECTURE.md`) — не реализован; пулы это просто таблицы + словари-кеши внутри
  `SQLiteAdapter`.
- Кешировать всё, включая `vals` — не помещается в RAM на реальных объёмах.

## Последствия

- Экономия места и ускорение `WHERE`/`JOIN`/`GROUP BY` по `(src, lb, id)`.
- В пулах копятся записи без ссылок (после архива/удаления) — нужна чистка
  ([`../roadmap/optimization.md`](../roadmap/optimization.md)).
- `id` глобально уникален в `ids` (не в рамках источника); `lbs` уникальна по `(src_id, name)`
  — см. [ADR-0005](0005-source-specific-labels.md).
