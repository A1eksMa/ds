# 0007. Заморозка репозитория на слое ядра-хранилища

- **Статус:** Принято
- **Дата:** 2026-08-29

## Контекст

Первоначальный замысел (`docs/attic/`, ноябрь 2025) описывал крупную систему: 11 компонентов,
двухуровневый движок обработки, Entity Manager, семантический маппинг, снэпшоты, YAML.
Реализация к 0.5.0a1 — компактное ядро (`domain/ports/adapters/persistence/config/service/cli`,
одна CLI-команда). Помимо кода в репозитории у автора уже сложился «обвес»: скрипты подготовки
данных, SQL-отчёты, код BI-аналитики, в планах — веб-интерфейс. Обвес специфичен для
предметной области; логика ядра — общая.

## Решение

Многослойная архитектура; **этот репозиторий заморожен на нижнем слое** — система записи:

- **В ядре:** приём данных, историзация, выдача состояния **одного источника** на момент
  времени (Level 1), жизненный цикл (архив/удаление/retention), управление сущностями схемы
  (merge/split/delete/rename над `srcs`/`lbs`/`ids`/`vals`), миграции схемы, оптимизация.
- **Вне ядра (отдельный будущий проект, вероятно JS + веб-UI):** семантический маппинг,
  разрешение коллизий между источниками по весам `p` (Level 2), управление приоритетами и
  состояниями пользователем, любой UI, доменная логика, BI.

Первичный артефакт ядра — **формат хранения (контракт)**, а не код. Это «движок хранения» +
«инструментарий инженера», **не** фреймворк / конвейер / ETL / приложение.

## Последствия

- `docs/proposals/` → `docs/attic/` с пометкой «не строим по этому».
- `docs/roadmap/` содержит только то, что сядет в ядро (список выше), а не весь исходный
  замысел. Семантика/Level 2/UI — явные non-goals ([`../explanation/scope-and-non-goals.md`](../explanation/scope-and-non-goals.md)).
- `ds get` и свёртка Level 1 были сняты ради минимума кода, затем переписаны заново —
  [`../reference/get-output-format.md`](../reference/get-output-format.md).
- Схема БД становится публичным интерфейсом для верхнего слоя → её стабильность и
  сверяемость с кодом критичны ([`../reference/database-schema.md`](../reference/database-schema.md)).
