# 0008. Схема БД не версионируется отдельно от кода

- **Статус:** Принято
- **Дата:** 2026-08-29

## Контекст

Схема БД — контракт, на который завязан вышестоящий слой ([ADR-0007](0007-scope-freeze-storage-core.md)).
Возник вопрос: нужен ли отдельный `SCHEMA_VERSION` и политика совместимости, независимые от
версии пакета `ds`.

## Решение

Отдельного номера версии схемы **нет**. Проект по сути монолитен; контракт для верхнего слоя —
это **тег версии `ds`**. Журнал совместимости — `releases/README.md` (там уже фиксируются
изменения схемы по версиям).

## Альтернативы

- Отдельный `SCHEMA_VERSION` + таблица `schema_migrations` + правила «minor не ломает» —
  оправдано для отчуждаемого формата с несколькими независимыми потребителями. Сейчас
  потребитель один и разрабатывается тем же автором. Преждевременно.

## Последствия

- Верхний слой пиннится на конкретную версию `ds`.
- Изменения схемы обязаны попадать в `releases/README.md` явным пунктом.
- Если/когда формат станет отчуждаемым (несколько внешних потребителей) — это решение
  пересматривается новым ADR.
- Инструменты миграции данных при изменении схемы всё равно нужны —
  [`../roadmap/schema-migration.md`](../roadmap/schema-migration.md).
